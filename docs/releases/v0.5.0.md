# ryzen-smu-cli v0.5.0

This release adds the read-only system telemetry stream used by CurveAlign's
Ultimate live dashboard and controlled health check. Existing command output,
including the v0.4.0 schema-1 `--stream-telemetry` contract, is unchanged.

## System telemetry schema 2

Start the stream with the complete Windows logical topology:

```powershell
.\ryzen-smu-cli.exe --stream-system-telemetry --interval-ms 500 `
  --targets 0:0,0:1,0:2,0:3
```

The accepted interval is 500 through 60000 ms. Targets are unique
`group:processor` pairs, canonically sorted by group and processor. Each
processor is 0 through 63. Windows must accept processor-group affinity for
every supplied target.

The first complete snapshot establishes APERF, MPERF, and AMD RAPL package-
energy baselines and emits no stdout. The second complete snapshot is sequence
zero. Each JSON line contains, in order:

```text
kind, schemaVersion, sequence, elapsedMilliseconds, timestampUtc,
measurementIntervalMilliseconds, acquisitionDurationMilliseconds,
vcoreVolts, cpuTemperatureCelsius, temperatureSource, packagePowerWatts,
packagePowerSource, targets
```

Each target contains `group`, `processor`, `aperfDelta`, `mperfDelta`,
`measurementIntervalMilliseconds`, and `effectiveMhz`, in that order. The
source constants are `tctl-tdie` and `amd-rapl-package-energy`.

```json
{"kind":"system-telemetry","schemaVersion":2,"sequence":0,"elapsedMilliseconds":500,"timestampUtc":"2026-08-12T00:00:00.0000000\u002B00:00","measurementIntervalMilliseconds":500,"acquisitionDurationMilliseconds":4,"vcoreVolts":1.1875,"cpuTemperatureCelsius":71.875,"temperatureSource":"tctl-tdie","packagePowerWatts":100,"packagePowerSource":"amd-rapl-package-energy","targets":[{"group":0,"processor":0,"aperfDelta":1250000000,"mperfDelta":2000000000,"measurementIntervalMilliseconds":500,"effectiveMhz":2500},{"group":0,"processor":1,"aperfDelta":1125000000,"mperfDelta":2000000000,"measurementIntervalMilliseconds":500,"effectiveMhz":2250}]}
```

Measurement intervals are actual monotonic deltas rounded to integer
milliseconds, not copies of the requested cadence. A 500 ms request may
therefore report 499 or 501. Package and target intervals can differ within
the bounded acquisition skew. Effective MHz is APERF delta divided by the
target's actual wall interval, and therefore includes idle residency. MPERF is
reported independently. Package power uses the modular 32-bit AMD RAPL
package-energy delta and the package interval.

## Fail-closed lifecycle

Vcore, Tctl/Tdie, package energy, and every target are acquired before a line
is written. Affinity failure, missing or reordered targets, MSR failure,
counter rollback, an implausible delta, or a sweep longer than half one cadence
terminates with exit code 6 without a partial line. An actual interval reaching
three requested cadences is stale; at 500 ms the boundary is 1500 ms.

After Windows suspend/resume, consumers must start a new CLI process. Its first
snapshot creates a fresh baseline, so a pre-suspend counter is never reused.
Ctrl+C remains a successful cancellation and restores affinity and releases
the controller session.

## Validation

The fixed 13-scenario suite now also covers schema-2 property ordering and
golden serialization, target parsing and ordering, baseline behavior, RAPL
wrap, APERF/MPERF deltas, read failure, reset, stale interval, slow sweep, and
target-identity rejection. Release guards additionally check parser-only
`--help`/`--version`, published files, archive membership, documentation,
native hashes, signatures, notices, and the pinned ZenStates-Core license.

Automated validation never reads real hardware. Privileged read-only hardware
qualification remains a separate manual release step.
